# AI 회화 학습 API

`/api/ai-study`는 로그인한 사용자만 이용합니다. 모든 요청에 Supabase 세션의 `Authorization: Bearer <access_token>`이 필요합니다. 서버에서 `auth.getUser`로 토큰을 검증하고 사용자 토큰으로 DB에 접근합니다. 관리자 키는 사용하지 않습니다.

| 요청 | 입력 | 응답 |
| --- | --- | --- |
| GET | `date=YYYY-MM-DD`, 생략하면 한국 날짜의 오늘 | `entry`, `history`, 선택 날짜의 `completed`, `today`, 오늘의 생성 시도 `used` |
| POST | `action: generate` | 오늘의 `entry`, 재사용 여부 `cached` |
| POST | `action: more`, `date`, `index: 0~4`, `scene` | 갱신된 `entry`, 추가 예문 시작 위치 `start` |
| POST | `action: complete`, `date`, `index: 0~4` | 완료한 표현의 인덱스 `completed` |

POST는 동일 출처의 JSON 요청만 받으며 본문은 최대 4KB입니다. 오류는 `{ error: 한국어 안내 }`로 응답합니다. 인증 오류 401, 입력 오류 400, 출처 오류 403, 동시 생성 409, 일별 생성 또는 예문 개수 초과 429, 미설정 503, 생성 지연 504를 구분합니다. AI와 DB의 원문 오류나 비밀값은 반환하지 않습니다.

사용자별 날짜 자료는 한 번만 저장합니다. 한 날짜에 표현 5개, 핵심 어휘 10개, 예문 30개를 만듭니다. 표현의 기본형·표시형과 핵심 어휘는 전각·반각, 공백과 문장 부호를 정규화해 기존 목록과 대조하고, DB 고유 키로 다시 확인합니다. 의미가 비슷한 표현은 프롬프트에서도 제외하지만 의미적 동의어까지 완전히 판별하는 기능은 아닙니다. 예문에 등장하는 일반 단어의 재사용은 허용합니다.

생성 실패와 중복 재시도도 하루 최대 10회에 포함합니다. 중복·형식 오류에 한해 한 번 재시도합니다. 예문은 같은 표현을 유지하며 4개씩 추가하고, 표현별 최대 30개까지 보관합니다. 학습 완료는 반복 요청해도 최초 완료 시각을 유지합니다. 한국 날짜의 자정이 지나면 새 날짜의 자료를 만들 수 있습니다.

생성 요청 원장의 횟수와 생성 시각은 사용자가 수정·삭제할 수 없습니다. 실행 중 예약은 완료·실패 시 해제되며, 프로세스 종료 시에는 4분 뒤 재시도할 수 있습니다. 모든 테이블에 사용자 소유권 RLS가 적용되고, 자료와 중복 방지 목록은 한 트랜잭션으로 저장됩니다.

# 일본어 작문 API

`/api/writing`은 기존 Supabase 세션의 `Authorization: Bearer <access_token>`으로 사용자를 확인합니다. POST는 동일 출처 JSON만 받고 최대 32KB입니다. 날짜는 한국 날짜 기준이며 미래 날짜는 받지 않습니다.

| 요청 | 입력 | 결과 |
| --- | --- | --- |
| GET | 선택 사항 `date=YYYY-MM-DD` | 공용 문제·생성 상태, 본인 답안·현재 버전의 채점, 날짜 목록, 오늘 채점 사용 횟수 |
| POST | `action: prepare` | 오늘 서버 전체가 공유하는 N3 문제 10개를 준비하고 조회 |
| POST | `action: save`, `date`, `answers` | 본인 답안 저장 후 조회 |
| POST | `action: grade`, `date`, `answers` | 답안 저장 → 미채점·수정한 문장만 AI 채점 → 결과 저장 후 조회 |

`answers`는 `{ index: 0~9, answer: 최대 600자, version: 마지막 조회한 버전 또는 0 }`의 배열입니다. 문항 중복·잘못된 버전·빈 배열은 거부합니다. 작성하지 않은 문항은 채점하지 않습니다. 각 문항은 의미 4점·문법 4점·표현 2점으로 총 10점이며, 10문항을 모두 채점하면 100점 만점입니다. 자연스러운 다른 정답과 한자·가나 표기 차이를 허용하도록 지시합니다.

공용 문제는 날짜를 기본 키로 사용하며 DB 잠금과 4분짜리 예약으로 동시 생성을 막습니다. 날짜별 준비 시도는 오류를 포함해 최대 3회이며, 성공한 뒤에는 새로운 세트를 만들지 않습니다. 기존과 동일한 한국어 문제는 정규화 키로 차단합니다. 매일 정해진 시각에 실행하는 스케줄이 아니라 당일 첫 준비 요청에 생성합니다.

모범답안·읽기·풀이·다른 정답은 비공개 스키마에 둡니다. 제출 전에는 공용 문제 API나 공개 DB 테이블에서 정답을 읽을 수 없습니다. 저장된 모범답안은 채점 성공 후 본인 결과에 포함됩니다. 사용자의 답안은 명령이 아니라 채점할 데이터로 전달합니다. AI 채점은 참고용이며 정확성을 보장하지 않습니다.

답안은 사용자·날짜·문항별로 버전을 올려 저장합니다. 기존 버전과 충돌하면 409로 거부하고, 현재 입력은 화면에 유지합니다. 과거 버전의 채점은 최신 답안 결과로 표시하지 않습니다. 같은 답안은 기존 채점을 재사용합니다. 새 채점은 오류를 포함해 계정별 한국 날짜 기준 하루 5회입니다. 채점 서비스 오류·사용 한도 초과에도 그 전에 저장한 답안은 유지됩니다.

쓰기와 비공개 정답 조회는 서버 전용 `WRITING_SERVER_SECRET`을 검증하는 제한된 RPC 작업만 수행합니다. DB에는 비밀값 대신 SHA-256 해시를 보관하며, 공개 래퍼는 호출자 권한을 사용하고 특권 함수는 비공개 스키마에 둡니다. 공개 테이블은 조회만 허용하고 개인 테이블에는 소유권 RLS를 적용합니다. 관리자 API 키는 사용하지 않습니다.

검증: `npm run test:writing`은 실제 Supabase SDK·fetch와 로컬 HTTP 의존성 모형으로 API를 검증합니다. `tests/writing-database.sql`은 오늘의 공용 문제가 없는 DB에서 관리자 SQL 세션으로 실행하는 롤백 전용 검사입니다. 임시 계정과 검증 자료를 포함한 모든 변경은 롤백합니다.

# 일본어 단어 배열 API

`/api/writing`은 기존 Supabase 세션의 `Authorization: Bearer <access_token>`으로 사용자를 확인합니다. POST는 동일 출처 JSON만 받고 최대 32KB입니다. 날짜는 한국 날짜 기준이며 미래 날짜는 받지 않습니다.

| 요청 | 입력 | 결과 |
| --- | --- | --- |
| GET | 선택 사항 `date=YYYY-MM-DD` | 공용 문제·섞인 단어 보기·생성 상태, 본인 답안·현재 버전의 결과, 날짜 목록 |
| POST | `action: prepare` | 오늘 서버 전체가 공유하는 N3 문제 10개를 준비하고 조회 |
| POST | `action: save`, `date`, `answers` | 본인 답안 저장 후 조회 |
| POST | `action: check`, `date`, `answers` | 모든 단어 사용 여부 검증 → 정답과 비교·답안과 결과 저장 → 조회 |

`answers`는 `{ index: 0~9, answer: 선택한 단어를 공백으로 연결한 문자열(최대 600자), version: 마지막 조회한 버전 또는 0 }`의 배열입니다. 문항 중복·잘못된 버전·빈 배열은 거부합니다. `save`는 조합 중인 문장도 저장합니다. `check`는 해당 보기의 모든 단어를 정확히 한 번씩 사용해야 합니다. 같은 표기의 단어도 별개의 칩으로 처리합니다. 비교 시 NFKC 정규화 후 공백과 문장부호를 제외하고 정답 또는 저장된 다른 정답과 비교합니다. 내부 결과는 정답 10, 오답 0으로 기존 테이블에 저장하며 화면에서는 정오답으로 안내합니다.

공용 문제는 날짜를 기본 키로 사용하며 DB 잠금과 4분짜리 예약으로 동시 생성을 막습니다. 날짜별 준비 시도는 오류를 포함해 최대 3회이며, 성공한 뒤에는 새로운 세트를 만들지 않습니다. 기존과 동일한 한국어 문제는 정규화 키로 차단합니다. 매일 정해진 시각에 실행하는 스케줄이 아니라 당일 첫 준비 요청에 생성합니다.

문제 생성 후 별도의 AI 요청으로 한국어와 일본어의 의미 대응, 명시된 정보의 누락·추가, 시제·부정·존대, 읽기와 문법을 검수합니다. 검수 결과는 모든 문항의 인덱스가 정확히 한 번씩 있어야 하며, 한 문제라도 부적합하거나 응답이 잘못되면 전체 세트를 저장하지 않습니다. AI 검수도 오류 가능성이 있으므로 완전한 번역 정확성을 보장하지는 않습니다. 저장된 정답을 교정하면 과거 정답으로 판정한 결과는 현재 결과에서 제외하고 기존 답안은 보존합니다.

정답 순서의 단어·모범답안·읽기·풀이는 비공개 스키마에 둡니다. 서버 전용 `puzzle_snapshot` 작업으로 조회한 후 정답 필드를 제거하고, 날짜·문항별로 안정적으로 섞은 `words` 배열만 API로 제공합니다. 단어 ID는 섞인 배열의 위치로 사용하여 정답 순서를 노출하지 않습니다. 기존 문제에 단어 배열이 없으면 서버의 일본어 `Intl.Segmenter`로 분할합니다. 정답과 문법 풀이는 정답 확인 후 본인 결과에 포함됩니다.

답안은 사용자·날짜·문항별로 버전을 올려 저장합니다. 기존 버전과 충돌하면 409로 거부하고 현재 조합은 화면에 유지합니다. 과거 버전의 결과는 최신 답안 결과로 표시하지 않습니다. 정답 확인은 하나의 DB 트랜잭션에서 답안과 결과를 저장하며 AI를 호출하거나 과거 채점 한도를 사용하지 않습니다. 한 문제를 확인해도 다른 문제의 미저장 조합은 유지합니다.

쓰기와 비공개 정답 조회는 서버 전용 `WRITING_SERVER_SECRET`을 검증하는 제한된 RPC 작업만 수행합니다. DB에는 비밀값 대신 SHA-256 해시를 보관하며, 공개 래퍼는 호출자 권한을 사용하고 특권 함수는 비공개 스키마에 둡니다. 공개 테이블은 조회만 허용하고 개인 테이블에는 소유권 RLS를 적용합니다. 관리자 API 키는 사용하지 않습니다.

검증: `npm run test:writing`은 실제 Supabase SDK·fetch와 로컬 HTTP 의존성 모형으로 API, 단어 배열 로직, 문항 컴포넌트를 검증합니다. `tests/writing-word-order-database.sql`은 관리자 SQL 세션에서 실행하는 롤백 전용 검사입니다. 사용하지 않은 과거 날짜에 임시 계정과 문제를 만들고 모든 변경을 롤백합니다. 단어 배열용 DB 변경은 `supabase/migrations/*_add_writing_word_order.sql`에 있습니다.
